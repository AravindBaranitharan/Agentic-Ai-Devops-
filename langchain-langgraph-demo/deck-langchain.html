◆ langchain-sessionWHAT IS LANGCHAIN01 / 12
the problem

One API call isn't an app

A raw LLM call gives you text
  • You still write prompt templating, output parsing, retries.
  • Grounding on your data (RAG) is a pipeline, not a call.
  • Tools, memory, and multiple models = lots of glue code.
LangChain gives you the glue
  • Standard components for each piece.
  • A common way to compose them (LCEL).
  • Swap models/vector stores without rewriting your app.
In one line: LangChain is the toolkit + the wiring standard for going from a single prompt to a real, testable LLM application.

A framework whose building blocks are Runnables — anything you can .invoke() — that snap together into pipelines.

◆ langchain-sessionDEFINITION03 / 12
the core idea

Compose with the pipe

LCEL — the LangChain Expression Language — wires components with |. Data flows left → right, each step a Runnable.

  • Get streaming, batching & async for free.
  • Swap any piece without touching the rest.
  • The same shape scales from a one-liner to a big DAG.
01_lcel_chain.py
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_messages([
  ("system", "Answer in ONE sentence."),
  ("human",  "Explain {topic} to a {audience}.")])

# THE CHAIN
chain = prompt | ChatOpenAI(model="gpt-4o") | StrOutputParser()
chain.invoke({"topic":"embeddings", "audience":"SRE"})
prompt | model | parser — that's LangChain in one line.

edge sample · tools

Let the model call functions

A tool is a plain function with @tool. create_agent hands the model the tools and runs the loop — it picks a tool, you run it, it answers.

model→ tool call→ run it→ answer
02_tools_agent.py
from langchain_core.tools import tool
from langchain.agents import create_agent

@tool
def get_pod_status(namespace: str) -> str:
    "Status of pods in a namespace."
    return "api-7f9: CrashLoopBackOff"

agent = create_agent("openai:gpt-4o", [get_pod_status])
agent.invoke({"messages": [user_q]})

◆ langchain-sessionUSE CASES07 / 12
where a chain stops

Straight lines have limits

A chain is a DAG — one direction
  • It can't easily loop (call tools, reflect, retry).
  • Branching on results gets messy.
  • Shared state across steps is implicit.
  • Pausing for a human? Persisting progress? Hard.
Real agents need cycles
think→ act→ observe

…then loop back to think again — until done.

Enter LangGraph → when your app needs loops, branches, shared state, memory, or a human in the middle, you graduate from a chain to a graph.
◆ langchain-sessionLIMITS08 / 12
comparison

LangChain vs LangGraph

LangChainLangGraph
Modelpipeline / DAG (a | b | c)graph / state machine (nodes + edges)
Flowlinear, one directionloops, branches, conditionals
Statepassed along (implicit)explicit, typed, shared
Memoryadd-onbuilt-in checkpointer
Human-in-loopmanualnative interrupt()
Best forprompts · RAG · extractionagents · retries · approvals
They compose: LangGraph nodes run LangChain components. Not either/or — LangChain is the parts, LangGraph is the orchestration.
◆ langchain-sessionCOMPARISON09 / 12
decision guide

Reach for LangChain when…

✓ Use LangChain
  • The flow is a straight line of steps.
  • RAG, extraction, summarization, classification.
  • Simple single-shot tool use.
→ Reach for LangGraph
  • You need a loop (agent that retries / reflects).
  • Branching, shared state, or memory.
  • A human must approve mid-flow.
Rule of thumb: straight line → chain. The moment you need a loop, a branch, memory, or a human → graph.

LangChain, in a breath

  • Build LLM apps by composing components — models, prompts, parsers, tools, retrievers.
  • Wire them with LCEL: prompt | model | parser.
  • Great for RAG, extraction, summarization, simple agents.

One line to remember: LangChain is the parts and the pipe — the standard way to assemble an LLM application.
